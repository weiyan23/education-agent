## 演示入口及操作

在已正确配置并启动的独立环境中：

1. 使用本地初始化账号登录 `/education/login`。
2. 教师进入侧栏“本版功能”：`/education/teacher/integration`。管理员对应 `/education/admin/integration`。
3. 阅读四个模块当前状态；切换“结果由错误转为正确”“连续错误记录”“评分更正记录”三个场景，查看预设事件与规则结果。
4. 页面始终保留“合成数据·只读”说明；样例不产生学习证据，不写入学生画像、推荐或成绩。
5. 教师点击“打开练习准备”进入有权限的课程生成页；实际可用模式以课程配置为准。管理员按钮进入“任务与能力”，不替代教师生成/审核。
6. 学生账号不可访问合成预览接口；学生学习页仍根据已有有效数据展示课程规则建议，只有已校验、未失效的研究结果才能显示为研究推荐。

加载失败可使用页面“重新加载”。页面没有一键触发完整研究闭环的按钮；推荐注册 503 是当前能力边界，不应改成无条件创建 queued 任务。

在专用合成环境演示 A 的合成生成时，由环境负责人将 `EA_GENERATION_FIXTURE_COURSE_ID` 设为已核对的专用合成课程 ID，再启动 API；该课程才出现“研究生成联调（合成样例）”。不要给真实教学课程启用合成发布。真实模型方式需另行配置 `EA_GENERATION_ENV_FILE`、课程策略和明确调用额度，当前交付不会自动配置或发起付费调用。

## 运行前置及数据边界

新工作树尚未配置它自己的数据库。代码齐备不表示本机依赖、账号或服务已准备完成，也不能把原工作区的私有配置直接复制进交付包。

按 [RUN_LOCAL.md](../../RUN_LOCAL.md) 的“在另一台电脑配置完整源码包”准备依赖、专用空 PostgreSQL/Redis 和私有连接配置。若已有隔离环境，先核对它对应的源码、数据库和端口，防止把新版操作写入旧 Demo 数据库。完成配置后，在仓库根目录执行：

```bash
cd demos/learnhouse-v2
python scripts/local_demo.py doctor
python scripts/local_demo.py start
```

启动成功后访问 `http://localhost:3300/education/login`。远程环境按运行说明转发 3300 端口；账号及随机密码只在本地初始化文件中查看。本阶段没有新增数据库 schema/迁移；首次部署仍需准备现有基线结构。

本阶段代码集成不使用私有 `.env`，不调用真实模型或执行学生 Java，不对已有演示库/真实业务库写入。后续本地初始化及业务验收会产生数据，必须使用单独合成环境，结果另行记录。密钥、Cookie、随机密码、数据库和 `.runtime` 不进入 Git 或交接包。

本周“最小端到端链”的目标是：一次有效业务作答/评分 → 持久化画像版本 → 推荐 → 合法学习内容入口 → 新作答/反馈记录 → 质量评估反馈。它不是承诺一周完成全部研究双闭环或证实学习效果提升。

### 每位组员的交接包

- 一个可审查的任务分支/PR，说明对应研究内容与产品页面，不提交环境私密文件。
- 改动文件、调用链、请求/响应样例、版本与权限约束；数据库有变更时提供迁移及回退说明。

- 下一位模块负责人实际消费的共用样例；不能只分别生成各自格式的“接口已完成”截图。
